# Stacker v0.6.1

Fix macOS startup aborts when CoreVideo cannot create the display link used by Avalonia's native render timer.
Stacker checks display-link availability before initializing Avalonia, waiting up to 30 seconds for a display
to become available. If it remains unavailable, startup returns a failure exit code and writes an explanation
instead of allowing an unhandled startup exception to terminate the process with SIGABRT.

Startup exceptions and otherwise unhandled managed exceptions are saved in `diagnostics/last-crash.log` under
the active application profile (including profiles selected with `--data-root`). No automatic restart or workspace
mutation is attempted after a failed startup. Wake/connect a display and launch again after an availability failure.

The diagnostic report found during this investigation was from the earlier 0.5.0 smoke process (PID 51303),
not evidence of a new 0.6.0 runtime crash. Additional reports are needed to attribute any different runtime failure.

Regression coverage includes a display becoming ready, persistent display failure without starting the workspace,
and preservation of startup exceptions. Packages target Windows x64 and macOS Apple Silicon.
