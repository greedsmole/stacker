# Stacker desktop design

A compact workbench for reviewing stacked Git changes. ENERGY 1 / RHYTHM 2 / MOTION 1.

Design foundation: Microsoft Fluent 2 patterns implemented with native Avalonia Fluent controls in Compact density. Shared spacing, type, shape, semantic colors and native control aliases live in `src/Stacker.Desktop/Design/FluentTokens.axaml`; application component appearances live in `src/Stacker.Desktop/Design/FluentControls.axaml`. Read [the design-system decision and component rules](docs/DESIGN_SYSTEM.md) when changing the UX.

Code is the focal point. The default selected-PR diff viewport must occupy at least 75% of window width and 75% of window height at 1060×640 and 1400×880; measure the visible viewport after intersecting it with its scroll container and window. The compact comparison header identifies the title and branch range without becoming a separate reading surface. Stack order and numbered layers provide the product's identity. Keep real branch names, file paths, line numbers and review state visible; do not introduce dashboard metrics or decorative cards.

Use charcoal and neutral light surfaces. A slightly raised chrome surface separates application navigation; a quieter header surface groups comparison controls. Blue identifies primary actions, focus and selected data rows. Segmented view and layout controls use neutral selection so they do not compete with the review action. File statuses use outlined Git letters so they remain readable without color. Diff additions and removals use subdued semantic fills and explicit textual markers; saturated neon fills overpower syntax and are excluded. Use Inter for compact, consistent interface text across platforms and monospace for code. Use explicit primary and secondary text colors in each theme, rather than reducing the opacity of inherited text. Controls use 4 px radii, segmented groups use 6 px, and there are no ornamental shadows, gradients or glow.

Stacks start collapsed and Files uses a 220 px default width. The two panes remain independently available on request. Focus temporarily hides both and the review inspector. Files uses one list or folder tree for the comparison, with separate groups when there are several layers. History uses the same controls in its file picker. Discussion and Review never open automatically, including on resize. Only an explicit action opens the 360 px inspector; dock it when at least 520 px remains for the diff, otherwise show Back to diff. Inline conversations and saved draft bodies start collapsed behind compact disclosures. Minimum content size is 1060 by 640. Settings from the previous layout adopt collapsed Stacks and the narrower default Files width once; subsequent explicit layout choices persist.

Settings and Refresh are named controls. Application navigation and pane controls share one 44 px toolbar. Keep the comparison header to one 52 px row and the file header to one approximately 36 px row. This layer, Through this layer, Discussion and Review remain visible. Stack maintenance and diagram commands open under Stack actions or PR tools; file expansion, wrapping, copy, navigation and file comments open under File actions. Command menus use native MenuFlyout/MenuItem controls with checked states and keyboard navigation. Multi-line commenting uses the contextual + beside the selected code. Maintenance and the command log live under More. Stack disclosure, button feedback, file navigation, inspector closing, keyboard navigation and resizing are immediate. Explicit pointer opening of the inspector retains a 200 ms, 10 px ease-out entry to explain the arriving panel. Reduce motion skips it. Escape closes Review and restores its opening trigger's focus. New controls must invoke existing actions or implement useful behavior; no decorative controls. Keep pending review text local until explicit submission.

Dialogs use a clear heading, scrollable form or diagnostic body, and persistent actions on a separate footer surface. Keep labels 5 to 6 px from their fields and related groups 14 to 16 px apart; proximity communicates the form structure. At their minimum dimensions, content scrolls before actions disappear. Escape cancels; the unsaved-work warning returns to editing. Labels describe fields and actions directly. Inline threads, drafts and composers fit the diff viewport even when unwrapped code requires horizontal scrolling.

History opens the current diff in the available workspace. Compact controls above it select the layer, version, and file. The file picker identifies the section for comparisons that include base changes or multiple layers. Less frequent comparison, blocker, and graph actions open from Tools. Disabled actions reflect missing layer, file, checkpoint, or version prerequisites. Clearing the layer also clears its comparison.

Search distinguishes an unavailable comparison, an invalid pattern and a valid query with no matches. Empty workspace and loading are separate states. Error diagnostics remain selectable and scrollable with an explicit dismiss action. Warning text uses semantic color with sufficient contrast on the notice surface in each theme.

Verify both themes, minimum window size, file collapse/restore, comparison selection and review layout after changes. Do not claim a full accessibility audit from source inspection or a successful build alone.
